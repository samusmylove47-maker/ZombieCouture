# Prior art: open-source AI-built music videos

Read-only survey of 19 shallow clones under a scratch folder (16 distinct trees), 2026-09-30. Nothing was run or installed. Every claim comes from reading files or grepping the clones; "unverified" marks anything taken from a README or list metadata without reading code.
Our target: procedural 3D bubblegum-pop video, three.js in headless Chromium/SwiftShader driven by Playwright, ffmpeg encode, audio timing from JSON.

Reuse rule: "code adaptable with attribution" only for MIT, Apache-2.0, BSD, ISC (with a real license text), CC0, Unlicense. GPL, AGPL, CC-BY-NC, no license, or unclear = idea only. A package.json `"license": "ISC"` with `"author": ""` and no LICENSE file is the `npm init` default, so it counts as unclear. Copied MIT code needs a THIRD_PARTY_NOTICES entry with the copyright line quoted in the per-repo notes; CC0 needs none legally, list it anyway for provenance.

## What nobody in this set has done

"Not found" means not found in these 19 directories by the greps and file reads named, not that it does not exist elsewhere.

1. **A rigged 3D character lip-synced to the sung words.** Grep for GLTFLoader, SkinnedMesh, SkeletonHelper, AnimationMixer, FBXLoader, .glb, .gltf, VRM: no code or asset in any directory. Viseme, blendshape, morph-target and lip-sync terms appear only in am-will (`singing(t, style)` mouth flaps, described as "so performances read without lip-sync", 2D), in eszn (phoneme tables that drive its own synthesised voice, not the on-screen mascot), and in docs and prompts. Word and syllable timings exist (mexicat `data/lyrics.json`, `syl`), but nothing consumes them to move a mouth. The list in C5 has a five-repo "Avatars" category advertising lip-sync (not cloned, unverified), so this is a gap in this set, not in the ecosystem.
2. **three.js materials and lights in a music video.** three.js is used by mexicat and andsnw (32 files each) and volker48 (7); none of it uses MeshStandard, Physical, Lambert, Phong or Toon materials or any three.js light, shadow map or environment map (unlit MeshBasic, ShaderMaterial and line materials only). Lighting exists only as hand-written GLSL in three mexicat/andsnw scenes, all shaded as engraving hatching: `shoggoth-glsl.ts` (raymarched tentacle and torus-knot creature, key and rim light, eyes with lids), `paperclips-glsl.ts` (key, rim, lamp, specular line), `ilya-glsl.ts` (room lit by a laptop screen: rectangle-light irradiance plus one shadow ray). None has a skeleton or a mouth. The single three.js-lit example is GeekyVenkatTuring `composer/src/styles/packs/studio.tsx` (meshStandardMaterial, ambient + directional + two point lights), for narrated explainers with primitive shapes and no characters. am-will's castShadow and roomLight are 2D canvas fakes. matthewmiglio's realism.md describes PBR sky and HDRI shading but the repo ships no scene (projects/ holds only .gitkeep). No glossy, candy or jelly plastic look anywhere; the nearest is a flat pastel 2D chapter (am-will `example-gangnam/src/ch/c06_montage.js`), and matthewmiglio's skill bans candy or pastel-toy palettes and bubble fonts outright.
3. **Software-GL cost budgeting per shot.** Present: scalar rules (mexicat "aim for < 25 ms/frame", ClaudeAnimationBase "aim for <= 1.5 s per frame", matthewmiglio "roughly 1-3 s per frame at most"), one measured SwiftShader number (jessecaple: 3.3 fps on its own bench scene), a probe with fallback (tictacked), and mexicat's `perf` (average ms per frame over a time range, run on a GPU). Not found: a per-shot cost table under SwiftShader tied to the shot list with a pass/fail budget, or a full-render time forecast built from it. jessecaple requires NVIDIA plus NVENC; mexicat's render.ts passes `--use-angle=metal`.
4. **QA that audits the finished timeline against the music.** Per-shot sheets exist (mexicat `sheet --cuts`, ClaudeAnimationBase, abhinavflac filmsheet.mjs) and tictacked's qa.py reads the shot list. Not found: a script that reads the shot list plus audio JSON and fails when a cut is off the beat grid or a caption starts before its word. Cuts are placed by snap helpers, and the only lead/late scorer (abhinavflac compare-timing.py) runs on timing data before rendering. Also not found: one per-shot report combining cost, flash, frozen/blank, sync and legibility. Checked: every script whose name contains check, qa, scan, lint, verify, audit, seam, jump, smoke or regress.
5. **Extruded or lit 3D lettering for lyrics.** No TextGeometry, troika-three-text or MSDF. Text is Canvas2D textures, opentype.js outlines as polylines or Path2D (mexicat type.ts), DOM/SVG, or art traced to vectors (abhinavflac).

### A1 mexicat_pdoom-video
- License: MIT, "Copyright (c) 2026 Giacomo Magnanini". README: the song and lyrics (`audio/`, `lyrics/`, `data/lyrics.json`) are not covered; fonts keep their own SIL OFL licenses.
- What: three.js + TypeScript (bun, Vite) engine that renders any song time t deterministically (linear-HDR half-float pipeline, GLSL passes, Canvas2D layers, GPU line batches) for the 156.65 s "I'm Upping My P(doom)" video; playwright-core drives it and streams frames to ffmpeg.
- Audio/lyrics contract: `data/audio.json` (beats, downbeats, sections, kick/snare/hat/vocal onsets, 100 fps rms/low/mid/high/vocal/drums/bass/other envelopes) through `app/src/engine/audio.ts`; word-level `lyrics.json` with `syl` sub-words through `lyrics.ts`.
- Beat-snapped cuts: `app/src/timeline.ts` `cut(q, nth=0, tol=0.02)` returns the time of the last beat at or before the first word of the quoted line; hard cuts on downbeats by default, crossfade only if overlapped.
- Analysis: `analysis/ctcalign.py` + `ctc_emissions.py` (MMS_FA and wav2vec2-LV60K fused, one global Viterbi over the song, garbage token, anchors), `align.py` (signal-based boundary refinement), `whisper_run.py`, `pron.py`, `analyze.py` (constant-tempo grid, kick-attack phase, envelopes), `qa_plot.py` and `zoom.py` (spectrogram, pitch, word boundaries).
- Harness: `app/scripts/render.ts` modes stills, sheet (`--cuts`, `--times`), plates, perf, video (`--samples auto`, `--shutter`, `--scale 2` for true 4K); WebSocket frame streaming; BT.709 tagging. Post and text: `app/src/engine/post.ts`, `type.ts` (opentype.js outlines, Path2D, text point sampling for particles, static Archivo width/weight instances), `lines.ts` (GPU capsule segments, 10k to 200k).
- Verdict: code adaptable with attribution, minus song, lyrics, lyrics.json.
- Weak spots: engraving-style line art and shader look, no three.js lights or lit materials (light only inside three raymarch shaders, see nobody #2); no SwiftShader timing exists for the raymarched G-buffer scenes (`shoggoth-glsl.ts`, `paperclips-glsl.ts`, `ilya-glsl.ts`); flags assume an Apple GPU (`--use-angle=metal`, render.ts:50); adaptive sub-frames multiply cost 4x to 324x; analysis constants tied to one song (`N_FRAMES = 7833`, hand-mapped section bars).
